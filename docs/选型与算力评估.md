# LLM 选型与算力评估 (私有化部署)

> 适用前提: 工艺参数/良率数据属于核心机密, LLM 与 Embedding 必须全内网私有化部署。
> 以下显存为经验估算区间 (含约 10~20% KV cache 余量, 按 8K 上下文), 实际以试跑为准。

## 1. 候选开源模型 (中文与指令能力强, 可商用)

| 模型 | 规模 | 特点 | 适用阶段 |
|---|---|---|---|
| Qwen3 (8B/14B/32B) | 密集 | 中文强, 生态成熟, 32B 性价比高 | 首选主力 |
| Qwen3-30B-A3B / 235B-A22B | MoE | 推理激活小、吞吐高; 235B 需多卡 | 并发量大后 |
| DeepSeek-R1-Distill (32B/70B) | 密集 | 推理链强, 适合复杂归因分析 | 第二阶段 |
| GLM 系列 | 密集/MoE | 中文与代码能力好 | 备选对比 |
| Qwen3-Embedding / BGE-M3 | 0.6~2GB | Embedding/Rerank | RAG 必配 |

> 采购时以当期最新版本为准; 模型许可证需过公司法务 (Qwen/GLM 主流版本均可商用)。

## 2. 显存估算与 GPU 配置

| 模型规模 | FP16 | INT8 | AWQ/GPTQ INT4 | 推荐硬件 | 适用 |
|---|---|---|---|---|---|
| 7~8B | ~16GB | ~9GB | ~6GB | 单卡 24G (RTX 4090) | 流程验证 |
| 14B | ~30GB | ~16GB | ~10GB | 24G 单卡 (4bit) / 48G | 部门试点 |
| 32B | ~64GB | ~34GB | ~20GB | 48G 单卡 (L20) 或 24G×2 | **推荐起步** |
| 72B | ~145GB | ~76GB | ~42GB | 80G×2 (A100) / 96G×2 (H20) | 高质量阶段 |

要点:
- **并发决定真实需求**: 上表是"单并发能跑"; 10 人同时用需预留 KV cache,
  建议按估算值 ×1.5~2 选卡, 或用 vLLM 的 continuous batching 降峰值。
- **量化优先**: 工厂问答场景 AWQ-INT4 精度损失可接受, 显存减半、
  同硬件可上更大模型, 是投入产出比最高的选择。
- Embedding (BGE-M3 约 2GB) 可与 LLM 共用一台服务器或单独小卡。

## 3. 部署方式对比

| 方式 | 成本 | 优点 | 缺点 |
|---|---|---|---|
| vLLM + 采购 GPU | 一次性硬件投入 | 数据不出厂, 长期成本低, 可复用 | 有采购/维保流程 |
| Ollama (试用) | 近零 | 半天跑通, 选型试错 | 并发弱, 仅限验证 |
| 租用区内算力 | 按月 | 无采购流程, 灵活 | 数据仍需出厂 (多数 fab 不允许) |
| 公有云 API | 按量 | 无硬件 | **涉密数据不可用**, 仅限脱敏知识类 |

**建议路径**: Ollama 跑 7B/14B 验证流程 (1 周) -> 采购 1 张 48G 卡 (L20)
跑 32B-AWQ 试点 -> 依并发与效果评估扩到 72B 或 MoE。

## 4. 试点推荐配置 (一台服务器)

- GPU: L20 48G ×1 (或 2×RTX 4090 跑 14B/32B-INT4 分卡部署)
- CPU/内存: 16 核 / 128GB (向量库 + 应用同机够用)
- 磁盘: 2TB NVMe (模型权重 20~60GB + 文档库)
- 软件: vLLM (OpenAI 兼容) + TEI (BGE-M3) +本项目脚手架
- 网络: 部署在办公网段, 经 IT 防火墙策略访问中间库, 与生产网隔离

## 5. 预算量级 (粗估, 以询价为准)

| 项目 | 量级 |
|---|---|
| L20 48G 单卡服务器 | 数万~十余万元级 |
| 2×A100 80G 服务器 | 数十万元级 |
| 人力 (2~3 人 × 2~3 月 MVP) | 按内部人月核算 |
| Ollama 试用阶段 | 0 (用现有带 24G 显卡的工站即可) |
