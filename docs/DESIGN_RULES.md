# Fab Bot 桌面端设计规则 v1.0

> 规则不是建议。评审可以直接指着编号要求修改。规则挡住了正确的事，就在同一个
> PR 里改规则并写明原因——不要悄悄违反。（格式借鉴 OpenMausBot DESIGN.md）

## 1. 原则

1. **默认安静。** 静止界面不闪烁、不计数、不抢注意力。拿不准就去掉。
2. **一个产品。** 新界面要像本来就在的：用既有 token、组件与措辞。一次性样式 = bug。
3. **命名而非解释。** 好标签胜过一段说明；需要一句话才能懂的控件先改名再重新设计。
4. **说人话。** 说用户知道的词："知识库"而不是"向量库"，"告警值守"而不是"watcher 轮询"。
5. **每个状态都被设计。** 空态、加载、错误、超长文本、窄窗口、亮暗皮肤——没人只发布 happy path。
6. **人人可用。** 键盘、触屏、读屏是设计的一部分，不是后续。
7. **借感觉，不借外形。** 可以被别的产品启发质感；不抄它的签名部件。

## 2. 色彩与 Token

- 一切颜色来自 Tailwind token（`ios.*` / `identity.*`）。**禁 raw hex**（第三方 logo 例外）。
- 身份色六色板：`identity-blue #0A84FF / green #30D158 / red #FF453A / orange #FF9500 / purple #BF5AF2 / cyan #64D2FF`，每个 bot 固定一色。
- 语义面：`bg-ios-bg`（页面）、`ios-card`（卡）、`hairline`（描边）、`ink-secondary`（辅助文字）。

## 3. 界面只有三个地方

**侧边栏**（导航与 bots）、**内容区**（当前模块）、**面板**（关于某个 bot 的一切）。新东西放进属于它的地方，不新增第四个地方。

- 不新增顶栏按钮：对话头部只显示当前 bot 与状态，其余进 bot 面板或菜单。
- 单个 bot 的设置在它的面板里；全局设置在设置页。同一设置不出现第二个入口。
- 侧边栏列表上方不加计数徽章与"需要你处理"摘要；状态标记放在所属行上。

## 4. Bots（联系人式智能体）

- 每个 bot 有：名字、emoji、身份色、一句职责、系统人设（后端注册表）。
- bot 回复的气泡头部使用它的身份色标记；用户在联系人列表里能一眼认出"在跟谁说话"。
- bot 不越界：数据分析师不答 SOP，工艺助手不写 SQL——提示词里写明职责边界。
- 新增 bot = 注册表加一条 + 无需新前端代码。

## 5. 状态

- 每个列表/面板实现：空态（带行动引导）、加载（骨架或 spinner）、错误（可重试）、长文本（截断+全文入口）。
- 错误消息说下一步："知识库未覆盖该主题——去知识库页导入相关 SOP"，而不是"查询失败"。

## 6. 安全文案（工厂特有）

- 写操作必须确认卡 + 说明后果；能撤销的用撤销替代确认。
- 拒绝时给出原因与出路："写操作已被拦截——数据查询仅支持只读 SELECT"。
- 引用来源永远可见；回答无来源时明确说"知识库未覆盖"。

## 7. 检查强制项

- `npm run build`（tsc 严格）；`bash scripts/check_all.sh`（五步门禁）；
- 新组件评审对照本文件逐条过。
